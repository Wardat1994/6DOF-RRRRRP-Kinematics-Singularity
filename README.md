# 6-DOF RRRRRP Robotic Manipulator
## Kinematics, Workspace, Jacobian, Singularity & Trajectory Analysis

A research-oriented Python implementation for the modeling and numerical analysis of a **6-joint RRRRRP serial robotic manipulator**, consisting of five revolute joints and one prismatic joint.

The repository provides a modular foundation for studying:

- Forward kinematics
- Denavit–Hartenberg modeling
- 3D robot visualization
- Reachable workspace
- Translational and geometric Jacobians
- Singular-value-based singularity analysis
- Manipulability
- Joint-space trajectory generation
- Cartesian end-effector trajectories
- Trajectory velocity analysis
- Singularity metrics along motion
- Automated numerical validation

---

## Robot Architecture

The generalized joint vector is

$$
q =
[\theta_1,\theta_2,\theta_3,\theta_4,\theta_5,d_6]^T
$$

where the first five joints are revolute and the final joint is prismatic.

| Joint | Type | Variable |
|---|---|---|
| J1 | Revolute | $\theta_1$ |
| J2 | Revolute | $\theta_2$ |
| J3 | Revolute | $\theta_3$ |
| J4 | Revolute | $\theta_4$ |
| J5 | Revolute | $\theta_5$ |
| J6 | Prismatic | $d_6$ |

### Geometric Parameters

| Parameter | Value |
|---|---:|
| $H$ | 0.5 m |
| $a_2$ | 1.0 m |
| $a_3$ | 0.8 m |
| $a_4$ | 0.6 m |

# Denavit–Hartenberg Model

The manipulator is modeled using the standard Denavit–Hartenberg convention.

| Joint | $a_i$ | $\alpha_i$ | $d_i$ | $\theta_i$ | Type |
|---|---:|---:|---:|---:|---|
| 1 | 0 | $\pi/2$ | $H$ | $\theta_1$ | Revolute |
| 2 | $a_2$ | 0 | 0 | $\theta_2$ | Revolute |
| 3 | $a_3$ | 0 | 0 | $\theta_3$ | Revolute |
| 4 | $a_4$ | 0 | 0 | $\theta_4$ | Revolute |
| 5 | 0 | $-\pi/2$ | 0 | $\theta_5$ | Revolute |
| 6 | 0 | 0 | $d_6$ | 0 | Prismatic |

Each link transformation is expressed as

$$
{}^{i-1}T_i =
\begin{bmatrix}
c_\theta & -s_\theta c_\alpha & s_\theta s_\alpha & a c_\theta \\
s_\theta & c_\theta c_\alpha & -c_\theta s_\alpha & a s_\theta \\
0 & s_\alpha & c_\alpha & d \\
0 & 0 & 0 & 1
\end{bmatrix}
$$

and the complete base-to-end-effector transformation is

$$
{}^0T_6 =
{}^0T_1
{}^1T_2
{}^2T_3
{}^3T_4
{}^4T_5
{}^5T_6
$$

# Forward Kinematics

The end-effector pose is represented by

$$
{}^0T_6 =
\begin{bmatrix}
R_0^6 & p_e \\
0 & 1
\end{bmatrix}
$$

with Cartesian position

$$
p_e =
\begin{bmatrix}
x \\
y \\
z
\end{bmatrix}.
$$

The implementation also calculates all intermediate joint positions, which are subsequently used for robot visualization and Jacobian construction.

Main implementation:

```text
src/kinematics.py
```

Example:

```bash
python examples/forward_kinematics_demo.py
```

# Jacobian Modeling

The project implements both translational and full geometric Jacobian representations.

## Translational Jacobian

$$
J_v \in \mathbb{R}^{3\times6}
$$

with

$$
v_e = J_v(q)\dot q.
$$

For revolute joints,

$$
J_{v_i}
=
z_{i-1}\times(o_6-o_{i-1})
$$

and for the final prismatic joint,

$$
J_{v_6}=z_5.
$$

## Angular Jacobian

For revolute joints,

$$
J_{\omega_i}=z_{i-1}
$$

while the prismatic joint has no angular contribution:

$$
J_{\omega_6}=0.
$$

## Geometric Jacobian

The complete geometric Jacobian is

$$
J_g =
\begin{bmatrix}
J_v \\
J_\omega
\end{bmatrix}.
$$

It relates joint rates to the end-effector twist:

$$
\begin{bmatrix}
v_e \\
\omega_e
\end{bmatrix}
=
J_g(q)\dot q.
$$

Main implementation:

```text
src/jacobian.py
```

# Jacobian Validation

The translational Jacobian is numerically verified using finite differences of the forward kinematic model.

For each joint variable,

$$
\frac{\partial p_e}{\partial q_i}
\approx
\frac{
p_e(q_i+\varepsilon)-p_e(q_i-\varepsilon)
}{
2\varepsilon
}.
$$

The numerical derivative is compared against the analytical Jacobian implementation through automated tests.

This provides an independent numerical validation of the differential kinematic model.

# Singularity Analysis

The repository evaluates robot configurations using numerical Jacobian indicators including:

- Jacobian rank
- singular values
- minimum singular value
- condition number
- translational manipulability

Singular Value Decomposition is calculated as

$$
J = U\Sigma V^T.
$$

The minimum singular value,

$$
\sigma_{\min},
$$

provides information about loss of motion capability and numerical conditioning.

A decreasing value of $\sigma_{\min}$ indicates movement toward a critical configuration.

# Translational Manipulability

The translational manipulability measure is

$$
w(q)
=
\sqrt{
\det(J_vJ_v^T)
}.
$$

It can also be expressed using the singular values of the translational Jacobian:

$$
w(q)
=
\prod_i \sigma_i.
$$

![Manipulability](results/manipulability_vs_theta3.png)

Lower manipulability indicates reduced Cartesian dexterity.

# Trajectory Generation

The project now includes joint-space trajectory generation between initial and final robot configurations.

For two joint vectors

$$
q_s
\rightarrow
q_f,
$$

intermediate configurations are generated and evaluated through forward kinematics.

The resulting Cartesian end-effector path is

$$
p_e(t)
=
\begin{bmatrix}
x(t) \\
y(t) \\
z(t)
\end{bmatrix}.
$$

Main implementation:

```text
src/trajectory.py
```

# Cartesian Velocity Analysis

End-effector Cartesian velocity is numerically calculated from the Cartesian trajectory:

$$
v(t)
=
\frac{dp_e(t)}{dt}.
$$

The scalar Cartesian speed is

$$
\|v(t)\|
=
\sqrt{
v_x^2+
v_y^2+
v_z^2
}.
$$

![Trajectory Speed](results/trajectory_speed.png)

This analysis can later be extended to acceleration, jerk, actuator velocity limits, and real-time control constraints.

---

# Manipulability Along the Trajectory

Manipulability is evaluated at every sampled robot configuration.

![Trajectory Manipulability](results/trajectory_manipulability.png)

This makes it possible to determine whether Cartesian dexterity deteriorates during motion.

# Minimum Singular Value Along the Trajectory

The minimum singular value of the translational Jacobian is also evaluated throughout the trajectory.

![Trajectory Sigma Minimum](results/trajectory_sigma_min.png)

This provides a trajectory-level singularity indicator rather than analyzing only isolated robot configurations.
